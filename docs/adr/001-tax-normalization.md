# ADR 001: 税抜・税込混在レシートの品目価格正規化

## Status

Accepted

## Context

仕様書では `items[].price` を税込の行合計とし、その合計とレシート合計を
±2円で照合する。一方、日本のレシートには税抜価格へ外税を後加算する商品と、
内税価格の商品が同時に記載される場合がある。

合計差額だけを税とみなす補正は、読み落とした商品を税と誤認して
`confirmed` にする危険がある。また、内税を一律加算すると二重計上になる。

## Decision

- VLM出力に、品目の印字価格、税率、内税・外税区分と、レシート記載の
  税率別内訳を追加する。
- 印字価格は `price_raw`、正規化後の税込価格は既存の `price` に保持する。
- 外税補正は、同じ税率の品目印字額合計、または品目印字額合計と外税額の和が、
  レシート記載の外税対象額と±2円で一致する場合に限る。レシートにより
  税率別対象額が税抜・税込のどちらで表示される場合にも対応する。
- 品目の税率が不明な場合は、品目印字額の部分集合と税率別対象額を照合する。
  税率別の品目グループが一意に決まる場合だけ対応付け、同額商品などで
  複数の組み合わせが成立する場合は推測しない。
- 複数の外税内訳がある場合は、候補となる外税額の組み合わせを補正前の
  品目合計へ加え、レシート合計と最小誤差で一致する組み合わせが一意な場合だけ
  採用する。合計差額から新しい税額を作ることはしない。
- 部分集合探索が20,000状態、外税グループが8件を超える場合は補正せず、
  計算量の増大と誤確定を避ける。
- レシート記載の外税額を品目印字額に比例配賦し、余りは端数の大きい順、
  同値なら品目順で1円ずつ配る。
- 内訳不足や対象額不一致では推測補正せず、既存の合計検証により
  `review` とする。
- SQLiteでは既存の `items.price` を正規化済み価格として維持し、
  監査用情報を別テーブルへ保存する。

## Consequences

- 既存のJSONフィールドとSQLite列は維持される。
- 税メタデータを出さない旧Ollama応答も読み取れるが、外税を安全に補正できない
  場合は従来どおり `review` になる。
- レポートは既存の `items.price` を集計すれば税込金額を利用できる。
